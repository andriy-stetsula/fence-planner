# Fence Planner — Map Drawing Engine

Реалізація механіки малювання паркану поверх карти за ТЗ
"Fence Planner. Технічне завдання. Механіка малювання та взаємодії поверх карти" (v1.0, 03.08.2026).

> **Карта:** ТЗ описує механіку в термінах Google Maps (GEN-001, GEN-008 та ін.).
> У цій версії як шар карти використано **Leaflet + OpenStreetMap** — безкоштовно,
> без API-ключа і без білінгу. Уся механіка малювання (state machine, snap, розміри,
> undo/redo) не залежить від конкретного провайдера карти: geo↔screen конвертація
> винесена в окремий модуль `src/geo.js`, а рендер — у `src/overlay.js`. Щоб перейти
> на Google Maps API, достатньо замінити ці два файли й ініціалізацію карти в
> `src/main.js` — решта коду (`draw.js`, `state.js`, `model.js`, `history.js`,
> `keyboard.js`) залишається без змін.
>
> Файл референс-макета `Fence_Planner_Desktop_Mockup_V44.html` не був наданий разом
> із завданням. Візуальний стиль тут — мінімальний і зроблений на основі текстових
> вимог ТЗ (розділи 5, 9.2, 19).

## Структура проєкту

```
fence-planner/
├── index.html              # каркас сторінки, підключення Leaflet
├── style.css                # мінімальний UI (панель інструментів, курсори)
├── src/
│   ├── model.js              # мінімальна модель даних (Додаток A ТЗ)
│   ├── geo.js                 # конвертація screen <-> map координат (GEN-008), Leaflet-специфічний шар
│   ├── state.js                # State machine редактора (розділ 4 ТЗ)
│   ├── history.js               # Undo/Redo (розділ 21 ТЗ)
│   ├── draw.js                   # малювання прогону + live dimension (розділ 6, 7 ТЗ)
│   ├── overlay.js                 # SVG-рендер, синхронізований з Leaflet map events
│   ├── keyboard.js                 # гарячі клавіші, KeyboardEvent.code (розділ 20, KEY-001)
│   └── main.js                      # точка входу, збирає все разом
└── README.md
```

## Що вже реалізовано (крок 1 з плану)

- [x] SVG-шар синхронізований з картою (Leaflet `move`/`zoom` events, GEN-008 —
      прив'язка в пікселях екрану, дані зберігаються в геокоординатах)
- [x] State machine редактора: `select`, `draw`, `dragging`, `editNumber`
      (розділ 4). Під час малювання перетягування карти вимикається (`map.dragging.disable()`),
      щоб клік не робив одночасно кілька речей (PTR-003).
- [x] Малювання прогону по кліках з живим розміром від першої ж точки (DRW-001,
      DRW-002), округлення кроком 0.1 м як налаштування, а не хардкод (DRW-003),
      захист від нульового сегмента (DRW-004), Finish run / Enter (DRW-005 — кнопка
      в фіксованому куті, не за курсором).
- [x] Мінімальна модель даних Run/Point (Додаток A) зі стабільними ID (HIS-004).
- [x] Undo/Redo кістяк (один pointerdown→pointerup = один крок історії, HIS-001, HIS-002).
- [x] Гарячі клавіші через `KeyboardEvent.code`, працюють у кириличній розкладці
      (KEY-001), і не спрацьовують коли фокус в input (KEY-002).

## Що ще НЕ реалізовано (наступні кроки)

- Snap/join механіка (розділ 9) — endpoint-to-endpoint, T-стик, гістерезис attach/detach
- Кути 90° / точний градус (розділ 10)
- Замкнені контури (розділ 11)
- Переміщення груп прогонів (розділ 12)
- Ворота: розпашні (розділ 13) і розсувні (розділ 14)
- Fence gap (розділ 15)
- Стовпи (розділ 16), об'єкти ділянки (розділ 17)
- Raked / Step-down мітки (розділ 18)

## Запуск

Ключ не потрібен. Просто підніми будь-який статичний сервер у корені проєкту:

```bash
npx serve .
```

Відкрий у браузері адресу, яку покаже термінал (типу `http://localhost:3000`),
обери інструмент "Draw a fence line" і клікай по карті.

## Наступний крок

Реалізувати `snap.js` — пошук найближчої цілі (SNP-001..005) з гістерезисом
(розділ 9.4), і підключити його в `draw.js` та в перетягуванні вільних кінців.
